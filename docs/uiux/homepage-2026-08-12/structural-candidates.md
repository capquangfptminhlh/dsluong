# AutoTax Homepage Structural Candidates — observed 2026-08-12

## Candidate A — Operational Spine (SHORTLIST / CHOSEN)
Desktop silhouette: full-width entry -> horizontal operational spine -> one active stage detail -> editorial capability index -> trust model -> FAQ -> final CTA.
Mobile silhouette: compact entry -> industry pill row -> vertical stepper -> grouped capability accordions -> trust -> sticky bottom CTA.
Future Leap: Industry Lens rewrites operational labels/emphasis by business type while preserving the same semantic capability set.

## Candidate B — Role Lens Control Board (SHORTLIST)
Desktop silhouette: role selector (Chủ cửa hàng / Thu ngân / Quản lý) across top -> full-width task board -> role-specific job lanes -> proof/trust footer.
Mobile silhouette: role picker -> today-task cards -> role action rail.
Future Leap: remember selected role locally and prioritize the most relevant capabilities on return visits.

## Candidate C — Proof-First Product Window (SHORTLIST)
Desktop silhouette: product UI window occupies first viewport; marketing copy sits below as annotation rail; visitors navigate real read-only demo states.
Mobile silhouette: phone-sized product window -> swipeable states -> concise explanations.
Future Leap: safe read-only sandbox using deterministic demo data, never fabricated customer metrics.

## Candidate D — Today Checklist (SHORTLIST)
Desktop silhouette: entry is a six-item business checklist (Bán hàng, Kho, Thu chi, Công nợ, Hóa đơn, Thuế) -> each item expands into what AutoTax controls -> capability appendix.
Mobile silhouette: native checklist feed with progress disclosure.
Future Leap: visitor chooses current pain points and gets a personalized onboarding path.

## Candidate E — Business Graph (SHORTLIST)
Desktop silhouette: central transaction node connected to sales/inventory/cash/debt/tax nodes -> selecting a node changes an adjacent explanation pane -> trust + FAQ.
Mobile silhouette: node graph becomes a vertical causal chain.
Future Leap: graph highlights dependencies and data lineage rather than just listing features.

## Rejected rough candidates
F — Generic SaaS bento: rejected as saturated.
G — Split hero + dashboard: rejected; identical family to current AutoTax.
H — Cinematic 3D shop: rejected for SEO/performance/product-proof mismatch.
I — Logo/proof wall first: rejected because AutoTax lacks a verified public proof dataset.
J — Price-plan first: rejected because pricing source of truth is not established.
K — Blog/editorial magazine first: rejected because commercial/product intent would be delayed.
L — Infinite spatial canvas: rejected for accessibility/mobile predictability risk.

## Silhouette decision
A/B/C/D/E remain visually distinguishable with color, branding, imagery and iconography removed. Candidate A is selected because it maps most directly to AutoTax's actual end-to-end data flow while remaining simple on mobile.
